**every displayed number comes from the same measured engine** the

## Scope decisions vs. the original plan sketch

The early plan draft in `DEVELOPMENT.md` (written before implementation)
listed a few specifics that the built system deliberately does differently:

| Plan sketch | As built | Why |
|---|---|---|
| `/api/v1/search`, `/api/v1/status`, `/api/v1/document/:id` | `/api/search`, `/api/stats`, `/api/documents/:corpus/:id`, + `/health`, `/api/config`, `/api/benchmarks` | no external consumers exist to justify a version prefix; corpus is part of the document path; status/config/benchmarks split for the UI's four windows |
| Zod validation | Fastify's declarative JSON Schema (AJV) | validation belongs to the transport layer, one schema per route, coerces query-string types, no second validation library; contract tests unchanged |
| OpenAPI served at `/api/v1/docs` | [`docs/API.md`](API.md) | documented deviation: the readable reference shipped instead of a generated spec; endpoints are 6 plain GETs |
| `npm run dev:api` / `build:web` | `npm run api` / `api:dev` / `web:build` | named consistently with the existing script family |
| Ctrl+K / ↑↓ keyboard-first navigation | Enter-to-search, Enter on result titles, full tab order, aria labels | descoped: demo flows are pointer+keyboard through real controls; no hidden keybinding layer to test |
| Settings persisted client-side | Settings window is a read-only reference; query options live in the Search window | options are visible where they are used; nothing silently persists across sessions |
| pino logging | opt-in (`logger: true` in `server.ts`), silent in tests | quiet test output, full request logs in production |

Nothing in the engine (`src/core`, `scripts/lib`) was rewritten, no
existing test was deleted or modified to accommodate M5 — the API reuses
the pipeline through one seam (`SearchService`).
